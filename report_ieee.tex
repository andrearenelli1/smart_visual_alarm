\begin{abstract}
Deploying ML inference directly on microcontrollers eliminates bandwidth overhead and privacy exposure inherent in cloud-based video surveillance. The main challenge is fitting a viable vision model within the severe memory and compute constraints of embedded hardware while maintaining alarm-grade precision. This paper presents a Smart Visual Alarm System on the ESP32-S3-EYE that addresses this challenge through fully on-device person detection: a custom MobileNetV1 retrained with quantization-aware training (QAT) running under TensorFlow Lite for Microcontrollers achieves 88.4\% precision at a false-alarm rate of 8.9\%, with end-to-end inference latency of 403\,ms ($\approx$2.48\,FPS) on the embedded hardware. A three-frame moving-average filter further suppresses spurious triggers in live video. Alarm events are published via MQTT to a Python backend that delivers real-time Telegram notifications. Evaluated on 48,287 held-out COCO 2017 images, the system achieves ROC-AUC = 0.856 and AP = 0.877.
\end{abstract}

ESP32-S3-EYE, TFLite Micro, person detection, MQTT, Telegram Bot, IoT,

\section{Introduction}
\label{sec:intro}

The proliferation of low-cost cameras in homes, offices, and public spaces has made video-based surveillance a cornerstone of modern security systems. Traditionally, these systems rely on continuous video streaming to remote servers or cloud platforms, where inference is performed centrally. This architecture, however, carries two fundamental costs. First, transmitting raw video over a network exposes sensitive visual data to interception, storage by third parties, and potential misuse, a serious privacy concern in residential and workplace deployments where occupants have a reasonable expectation not to be recorded and analysed off-premises, as exemplified by the well-documented Amazon Ring case~\cite{ftc2023ring}. Second, continuous video streaming is bandwidth-intensive: a single 720p camera at modest quality can consume several Mbps of uplink, making cloud-based inference economically and practically unviable in bandwidth-constrained or large-scale deployments. Edge computing addresses both issues by pushing inference directly to the data source, so that only high-level semantic events, rather than raw pixels, ever leave the device.

Realising vision-based inference on embedded hardware is, however, far from straightforward. Microcontrollers (MCUs) typically operate with tens to hundreds of kilobytes of SRAM, no dedicated GPU, and clock speeds in the hundreds of MHz, orders of magnitude below the resources assumed by standard deep learning frameworks. Fitting a convolutional neural network capable of meaningful person detection within these constraints requires aggressive model compression (quantisation, architecture search) and careful memory management, all while meeting real-time latency requirements suitable for an alarm application.
A complete Smart Visual Alarm System is presented that addresses the above challenges end-to-end on a single embedded device. The main contributions are: (i) a fully on-device person detection pipeline on the ESP32-S3-EYE, combining a custom QAT MobileNetV1 with a three-frame moving-average filter for robust alarm triggering without any cloud dependency, (ii) a lightweight MQTT-based event notification architecture in which raw video never leaves the device and only compact JSON descriptors are transmitted, (iii) a custom MobileNetV1 retrained with quantization-aware training that recovers the accuracy degraded by post-training quantisation, outperforming the stock PTQ int8 model (ROC-AUC\,=\,0.856 vs.\ 0.823 on the held-out test set) at zero additional inference cost, and (iv) a systematic evaluation on 48,287 held-out COCO 2017 images (training offset 70{,}000) demonstrating ROC-AUC $= 0.856$, AP $= 0.877$, and $88.4\%$ precision at a false-alarm rate of $8.9\%$ (firmware default $\theta\!=\!0.60$), with a hardware inference latency of $403$\,ms on the target MCU.

\subsection{Overview}

The system comprises three tiers (Fig.~\ref{fig:arch}): the
ESP32-S3-EYE firmware, a Mosquitto MQTT broker, and a Python/Telegram
backend. Raw video frames never leave the device: only compact JSON event

The notification pipeline follows a \emph{Publisher-Subscriber} pattern,
decoupling event generation from consumers.

\subsection{On-Device Inference}

TFLite Micro \cite{tflitemicro} operates on a statically allocated
100\,KB tensor arena placed in PSRAM to preserve on-chip SRAM for the
RTOS and network stacks (relocating the arena to internal SRAM yielded
no measurable latency improvement and disrupted LCD DMA transfers,
so PSRAM allocation was retained). Input images are resized to $96\!\times\!96$
pixels and converted to signed 8-bit integers before feeding the
quantized MobileNetV1 model. The model outputs a \emph{person score}
dequantised to float. The deployed model is a custom MobileNetV1
retrained with quantization-aware training (QAT), replacing the
stock post-training-quantised model shipped with the
\texttt{esp-tflite-micro} repository~\cite{esptflitemicro}.

\subsubsection{MobileNetV1 Architecture}

MobileNetV1 \cite{mobilenet} is a lightweight convolutional neural
network designed for deployment on resource-constrained devices. Rather
than relying on standard convolutions throughout, it introduces
\emph{depthwise separable convolutions} as the main building block. A
depthwise separable convolution factorises a standard $k{\times}k$
convolution into two sequential operations: a per-channel $3{\times}3$
\emph{depthwise} filter, which applies a single filter to each input
channel independently, followed by a $1{\times}1$ \emph{pointwise}
convolution that linearly combines the outputs across channels. This
factorisation yields a reduction in multiply-accumulate operations
(MACs) with respect to a standard convolution of:
\begin{equation}
  \frac{\text{DW-Sep MACs}}{\text{Std Conv MACs}}
  = \frac{1}{C_o} + \frac{1}{k^2}
  \approx \frac{1}{9} \quad (k{=}3,\; C_o \gg 1)
  \label{eq:dwsep}
\end{equation}
making MCU deployment feasible without a substantial loss in
representational capacity.

The architecture (Fig.~\ref{fig:mobilenet}) opens with one $3{\times}3$
convolution followed by 13 depthwise separable blocks, global average
pooling, and a softmax classifier. The depth multiplier $\alpha\!=\!0.25$
scales all channel counts uniformly, yielding 213{,}272 parameters and
${\approx}7.2$\,MMAC.

The original \texttt{esp-tflite-micro} model uses \emph{post-training
linear quantization} (PTQ)~\cite{tflitemicro}: each weight is mapped to
a signed 8-bit integer via $r = S(q-Z)$, where $S$ is a per-channel
scale and $Z$ is the zero-point. This compresses storage without
additional training, but calibrating quantisation scales post-hoc
introduces rounding noise that the model was not trained to tolerate,
degrading accuracy (see Section~\ref{sec:detquality}).

\subsubsection{Quantization-Aware Training}

Quantization-aware training~\cite{qat} addresses the PTQ accuracy gap
by simulating quantisation noise during the forward pass via
\emph{fake-quant} operators inserted after each weight and activation
tensor. The model therefore learns weight distributions that are robust
to 8-bit rounding, yielding a quantised network whose accuracy closely
tracks the float32 baseline.

The custom model retrains the MobileNetV1 backbone
($\alpha\!=\!0.25$) using the Keras QAT API. Three architectural
adaptations were required to train from the available ImageNet-pretrained
weights and export cleanly to TFLite:
\begin{itemize}
  \item \textbf{Gray-to-RGB adapter.} The OV2640 camera delivers
    grayscale frames, but the ImageNet-pretrained backbone expects a
    3-channel input. A \texttt{Concatenate} layer replicates the single
    luma channel three times before entering the backbone. This maps to
    a \texttt{CONCATENATION} op in the TFLite graph.
  \item \textbf{Global average pooling.} \texttt{GlobalAveragePooling2D}
    computes the spatial mean over $H{\times}W$ and exports to TFLite
    as a \texttt{MEAN} op (rather than \texttt{AVERAGE\_POOL\_2D} used
    by a fixed-kernel pooling layer).
  \item \textbf{Dense classifier head.} A \texttt{Dense(2,
    activation=``softmax'')} layer replaces the $1{\times}1$
    Conv2D classifier of the stock model, mapping to a
    \texttt{FULLY\_CONNECTED} op followed by \texttt{SOFTMAX}.
\end{itemize}
The resulting TFLite graph uses seven ops:
\texttt{CONV\_2D}, \texttt{DEPTHWISE\_CONV\_2D},
\texttt{FULLY\_CONNECTED}, \texttt{MEAN}, \texttt{CONCATENATION},
\texttt{SOFTMAX}, and \texttt{QUANTIZE}.
Model size is 304.2\,KB int8 (vs.\ 293.5\,KB for the stock PTQ model), a negligible
increase. Hardware inference latency on the target device measures ${\approx}403$\,ms
(${\approx}2.48$\,FPS); the QAT-specific \texttt{QUANTIZE},
\texttt{CONCATENATION}, \texttt{MEAN}, and \texttt{FULLY\_CONNECTED}
ops collectively contribute ${\approx}13$\,ms of the total.

\subsection{Detection Logic and Alarm Trigger}

A moving-average filter with window $W\!=\!3$ frames smooths transient
noise:
\begin{equation}
  \bar{s}_t = \frac{1}{W}\sum_{k=0}^{W-1} s_{t-k}
  \label{eq:mavg}
\end{equation}
At ${\approx}2.48$\,FPS, $W\!=\!3$ spans ${\approx}1.2$\,s, sufficient to
suppress single-frame false positives while preserving sustained detections.
An alarm fires when $\bar{s}_t \geq \theta$ and at least $C_{\min}$
seconds have elapsed (defaults: $\theta\!=\!0.60$, $C_{\min}\!=\!10$\,s);
all three parameters are exposed as \texttt{menuconfig} options.
On alarm, the firmware blinks the onboard LED and publishes:
\begin{lstlisting}[language={}]
{"event_id":42, "confidence":0.87, "timestamp_ms":123456789}
\end{lstlisting}

Fig.~\ref{fig:livescore} illustrates the smoothing effect of the
moving-average filter on a representative 120-frame sequence captured
during a live deployment.

\subsection{Python Backend and Telegram Notification}

A Python script subscribes to the MQTT topic via \texttt{paho-mqtt},
validates each alarm payload, plays a local audio alert, and dispatches
a notification via the Telegram Bot API containing the event ID,
confidence, and timestamp. Credentials are passed via environment variables.

\subsection{Detection Quality}
\label{sec:detquality}

Both models were evaluated on the held-out test set: the 48{,}287
COCO\,2017 train images from index 70{,}000 onward, i.e.\ the portion
never seen during QAT training. Labels follow the Visual Wake Words
(person / no-person) layout~\cite{vww}. Preprocessing replicates the
firmware pipeline: BT.601 luma conversion and signed-8-bit quantisation.

Overall, ROC-AUC\,=\,0.856 and AP\,=\,0.877 on the held-out test set
(Figs.~\ref{fig:roc}--\ref{fig:sweep})
confirm good discriminative capacity despite int8 quantisation. The firmware-default $\theta\!=\!0.60$ was selected by combining

Per-frame recall (57.5\,\%) is partially compensated by the moving-average

high scores that consistently exceed the threshold, while isolated false
positives are averaged down by surrounding low-score frames, effectively
reducing the live false-alarm rate below the per-frame FAR reported here.

negatives far outnumber false positives, confirming the system errs toward
silence. COCO\,2017 covers a wide range of non-surveillance scenes and
predominantly 4:3 images whose square-crop resizing distorts person
silhouettes~\cite{esptflitemicro}; per-frame metrics therefore
underestimate operational performance.

\section{Conclusion}
\label{sec:conclusion}

This paper presented a complete Smart Visual Alarm System running fully on the
ESP32-S3-EYE: on-device TFLite Micro inference, moving-average alarm
logic, MQTT\,QoS\,1 event publication, and Python/Telegram notification.
Raw video is never transmitted: only compact JSON descriptors leave the
device. A custom MobileNetV1 was retrained with quantization-aware
training, recovering the accuracy degraded by post-training quantisation:
on the held-out test set (48{,}287 COCO\,2017 images, offset 70{,}000),
QAT int8 achieves AUC\,=\,0.856 and AP\,=\,0.877 vs.\ AUC\,=\,0.823
and AP\,=\,0.858 for the stock PTQ int8, with a measured inference latency of
403\,ms (${\approx}2.48$\,FPS) and a 304\,KB model footprint
(Table~\ref{tab:ptq_vs_qat}). The firmware threshold
$\theta\!=\!0.60$ provides 88.4\,\% precision at 8.9\,\% FAR,
and the three-frame moving-average filter further reduces the
effective false-alarm rate on live video.
A MobileNetV2 candidate was measured at $1{,}919$\,ms
(0.52\,FPS, Table~\ref{tab:v2_efficiency}), $4.8{\times}$ slower than
MobileNetV1 and incompatible with the 1\,s alarm-window requirement,
confirming that any accuracy improvement must come at lower---not
higher---computational cost on this hardware.

Future work includes: replacing the backbone with MCUNet~\cite{mcunet},
which targets higher accuracy at comparable or lower memory and MAC
budgets; and re-benchmarking on a surveillance-specific dataset (covering
typical indoor and outdoor camera viewpoints) to obtain accuracy
estimates more representative of operational deployments.
